# 启动故事生成并进行人工测试

## 本机入口

完整前后端工程位于 `H:\Projects\my-legend-handoff-20261111`，不是通用引擎目录 StoryGenerate。

故事专用入口是 `ops/my-legend/Start-StoryManualTest.ps1`。它启动独立 PostgreSQL、角色目录 API、业务 API、新故事 Worker、H5 前端；不启动声音、舞台或旧生成 Worker。旧的“启动交互式前端.cmd”会连带启动媒体，本轮请使用新入口。

需要 Docker Desktop 已启动、PowerShell 7.4+。本机已有 `.venv-interactive` 和前端依赖，直接运行：

```powershell
Set-Location H:\Projects\my-legend-handoff-20261111
.\ops\my-legend\Start-StoryManualTest.ps1 -KeyFile "$env:USERPROFILE\.codex\runtime\story-acceptance-20261111\asset-b.dpapi"
```

KeyFile 是当前 Windows 用户此前保存的加密聊天模型密钥，不是明文密钥；不要改用此前返回 401 的另一份资产。也可预先安全设置 DRAMA_LLM_API_KEY 并省略 KeyFile。换电脑时须重新配置密钥及 Python/Node 依赖，不要直接复制 DPAPI 文件。

成功后打开 `http://127.0.0.1:5193/#/pages/story-session/index`。首次进入点击“开始创作”进行本机登录，再进入故事页。此入口使用“墨羽、灵墨”两个明确的测试身份，不依赖同事的舞台素材目录；生成正文仍调用真实聊天模型。图片供应商默认关闭，页面会提示“背景生图未启用”。

启动和登录不发起模型生成，点击“开始一起创作”、修改或重试后才可能产生模型调用。请先完成一篇短剧，核对流程后再增加测试量。

## 推荐人工测试顺序

| 顺序 | 操作 | 观察重点 |
|---|---|---|
| 1 | 选短剧、帮我构思、两个角色；高级题材选生活治愈，其他用默认值；开始一起创作 | 不填写灵感也能完成；出现三个不同方向 |
| 2 | 点一个方向，等大纲完成 | 能看到标题、核心冲突、角色关系、分幕；预览不能直接确认 |
| 3 | 点击更轻松、开放式结局或突出一个角色 | 大纲重新构思，旧版本不被自动确认；变化符合所选要求 |
| 4 | 点击“按这个方向写剧本” | 正文逐幕推进，无须逐幕点击继续；正式分幕替换预览 |
| 5 | 写作期间选第 2 幕，选“从这里调整后续”，点更温暖或保留悬念 | 先显示已接收；到边界暂停，展示影响范围；确认后重新出大纲，再确认创作 |
| 6 | 等待剧本完成，阅读后点击“确认当前剧本” | 停在“剧本已确认”，不会出现声音或动画制作任务 |
| 7 | 导出剧本与背景规格 | 下载 JSON；有当前版本、确认状态、内容指纹、正文和背景规格 |
| 8 | 选择第 1 幕、“只改这一幕”、增加互动；确认范围及新大纲 | 只重做目标幕，其他幕正文应完全相同；旧确认版本保留在导出中 |
| 9 | 写作期间刷新页面，或离开再返回 | 恢复同一会话，已完成正文保留，不另创建重复故事 |
| 10 | 新故事写作中点取消，再刷新 | 状态保持已取消，不再启动下一幕；已发出的请求不能据此认定未计费 |
| 11 | 新建长剧，默认六集，大纲阶段改三集；确认并完成首集 | 有三集概要，只展开并生成当前集 |
| 12 | 首集确认后点“继续下一集” | 生成第 2 集，继承人物、前集事实和主线；不重做第 1 集 |

第一次建议先做 1–7，第二次检查 8–10，最后再测长剧。真实生成可能需要数分钟，页面展示实际阶段而非虚假百分比。看到“等待边界”时等待当前幕结束，不需要连续点击同一个按钮。

如果故事已经全部完成，可以在定稿后测试指定幕修改；只有选择“从这里调整后续”才允许影响之后的幕。短剧的结局控制完整故事；长剧需分别设置本集收束及系列最终走向。

## 阅读时如何判断内容质量

- 人物身份、说话习惯和已知信息是否一致，有无未选择的角色突然发声。
- 每一幕是否有目标、行动、阻力与结果，前后事实和物品状态是否衔接。
- 点选的“更轻松、更温暖、保留悬念”等是否落实在实际剧情，而不只是标题变化。
- 单幕改写是否保留其他正文；指定修改后续时，受保护前文是否完全保留。
- 短剧是否收束，长剧是否完成本集局部目标并留下合理主线。

“已确认”表示选择当前版本，技术检查通过不代表文学或语义质量已由人工认可。建议记录会话 ID、目标幕、操作和不符合预期的原句，方便复现。

## 停止与重启

```powershell
Set-Location H:\Projects\my-legend-handoff-20261111
.\ops\my-legend\Start-StoryManualTest.ps1 -Stop
```

停止前先在页面取消尚未完成的生成。关闭浏览器不会停止 Worker。停止入口核对 PID、启动时间和命令后，仅结束自己的进程及带专用标记的数据库容器，不删除数据库或故事记录。重启仍使用上面的启动命令，已有会话会保留。

数据和日志：`H:\Projects\my-legend-handoff-20261111\runtime\story-manual-test`。数据库容器为 `storygenerate-manual-test`，端口 25440，API 为 8895/8897，前端为 5193。测试数据与之前验收库、原声音制作任务隔离。

## 排错

| 现象 | 优先检查 |
|---|---|
| 5193 打不开 | frontend.err.log、Docker 状态、是否使用 PowerShell 7 |
| 启动提示端口冲突 | 先停止占用端口的其他测试环境；脚本不会结束不属于自己的进程 |
| 没有角色或开关未启用 | 应使用新故事专用入口，不能只运行 npm 或旧 API；启动器会核验这两项 |
| 一直构思、没有内容 | story-worker.err.log；确认 Worker 仍在运行，模型服务可用 |
| 401 或模型配置失败 | 当前密钥/网关权限，不能通过反复点按钮修复认证错误 |
| 提示版本更新 | 阅读刷新后的内容再确认，确认类操作不会自动确认新稿 |
| 提示供应商结果待核对 | 保存会话 ID，停止重复提交，先核对供应商调用结果与费用 |
| 提示背景未启用 | 本人工测试默认如此，不影响故事生成；聊天模型资产不能当图片服务使用 |

新电脑完整安装、正式业务身份和下游接入要求，见《故事生成独立交付与接入契约_20261112.md》。专用本机入口不是正式多用户部署方案。
