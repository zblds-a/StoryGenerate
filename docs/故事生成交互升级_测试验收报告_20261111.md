### 实际验证出的修复

1. 短剧的概要数量用运行时 Schema 固定为 1，长剧固定为计划集数；短剧输入不再带“系列六集”歧义。
2. Writer 的说话角色采用获批 ID 枚举；对白不允许用 null 掩盖第三人发声。
3. 行类型限定 dialogue/narration/sfx/music/action，阻止模型生成未约定的 audio 行。
4. 按已完成正文计算剩余字数预算，结构校验能给出实际超量字符数；仅对时长硬错误允许一次最后一幕定向修复。
5. 单幕修改的保护后缀不能被自动时长修复改写；预算耗尽时返回可定位错误，用户可选择更早的修改起点。
6. 故障诊断保留异常类型和校验位置，不把供应商任意错误文本或凭据发送给用户。

## 3. 调用与用量统计

按 call_id 对所有会话最新完整快照去重，真实故事阶段共 **93 次模型尝试**，其中 **3 次用量未知**：一次用户在途取消、两次网关断流。

供应商 reported 用量合计：输入 **232,361 Tokens**，输出 **151,882 Tokens**。输出可能包含供应商计入 completion 的推理 Token，不再额外重复加算推理量。

上述数字包含已失败的结构尝试和恢复调用，不只是最终成功内容。网关连通探测的 4 次请求单独计算，其中资产 B 的两次成功返回了用量，未混入故事统计。没有供应商单价与账单对账，本文不推导人民币金额；未知用量也不是免费。

### 生产全量的 14 项失败如何处理

- **11 项**在旧视觉/媒体链路读取 `basic_pixel/1.0.0/actors.png` 时失败。仓库固定源码快照没有随附该演员图集及配套素材，必须由素材维护方提供原始、可验证且有许可的资源；不能制作占位图冒充真实素材通过。
- **1 项**组合音频原生缓存测试在全组执行中进入 AUDIO_REQUIRES_MANUAL_RECOVERY；独立复测通过，尚需同事在实际音频配置和完整环境中确认全组隔离性。
- **2 项**Windows 子进程取消/截止测试在全组运行时失败，独立复测通过；不能把该结果外推为所有环境取消竞态都已通过。
- **4 项跳过**不计通过，保留原套件的环境/能力门槛。

环境准备中已恢复固定依赖源码、安装科学计算及 SQLite checkpoint 依赖、配置独立 Dart 3.14.0 与 FFmpeg。缺失的音频配置通过明确标记的、无凭据、禁止网络测试模板补齐，测试用音频由现有夹具生成，不是供应商 TTS 产物。

发现仓库测试引用了被 Git 忽略的 audit_media_clock.py，现将只读 PCM 归一化互相关见证函数放进生产包 audio_alignment.py，保留原延迟/静音/截断检查。该补充不宣称恢复了旧验收脚本中的全部视频审计功能。

## 5. 对上线和联调的建议

可以开始：合并评审分支；联调角色目录、选项、方向选择、大纲与剧本确认、逐幕事件、修改范围、重连及确认后来源桥接。可先用 output=script，避免将供应商/素材未准备好的问题混进故事接口。

仍不能承诺：首稿或全流程 100% 成功；所有网关原生 SSE 请求稳定；任意长剧稳定时延；真实图片、TTS、音效、完整舞台或玩具硬件已经验收。

网关原生流式目前出现两次未知结果断流，建议同事联调时同时保留按幕返回模式，并遵守“不对未知调用自动重试”。本批非流式短剧与续写已完成，但它们不是同一固定 Plan 的公平速度 A/B，不能用 168.6 秒和 211.6 秒计算通用加速率。

后续发布门：补齐合法素材和真实媒体供应商配置；在最后冻结版本上用一致角色、固定 Plan 和模型参数跑独立样本；单列首稿、有限修复、用户主动修改和供应商故障；再进行人工内容与听感验收。
