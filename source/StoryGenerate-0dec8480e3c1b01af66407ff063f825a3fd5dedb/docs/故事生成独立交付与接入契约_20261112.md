# 故事生成独立交付、启动与接入契约

日期：2026-11-12。本文是当前交付口径，优先于 11 月 11 日文档中的媒体自动桥接方案。

## 1. 本次范围与结果

本次自行实现故事前端、业务 API 适配、持久会话、独立 Worker 和联调测试。新入口只交付故事，不启动后续配音、声音制作、剧本演绎、舞台或动画任务。原入口及其下游流程不改。

此前分支中加入的媒体来源迁移、来源登记、确认后创建 production flow，以及与音频测试有关的修补，已从最终集成树撤回。对照集成基线检查，原 production/repository.py、performance_production.py、test_media_clock_evidence.py 内容保持一致；不新增 audio_alignment.py 或 007_interactive_sources.sql。旧数据库若曾自行应用旧补丁的来源表，本次不会删除该表或其数据，但新入口不使用它。

| 用户操作 | 已实现行为 |
|---|---|
| 首屏 | 选择角色、短剧/长剧、构思/一句灵感/续写；其他偏好折叠 |
| 纯选项构思 | 一次返回三个方向，不要求填写灵感 |
| 题材 | 国风奇幻、冒险成长、悬疑推理、生活治愈，后端映射 Mode/Genre/Recipe |
| 长剧 | 默认六集，先规划系列、只生成当前集；大纲确认前可重新规划集数 |
| 结局 | ending 表示当前集收束；series_ending 表示系列最终走向，未到最后一集不得提前完结主线 |
| 大纲 | 展示名称、冲突、关系、分幕、系列概要；可选结局、突出角色、换方向，再确认具体指纹 |
| 正文 | 自动逐幕推进，显示真实阶段、预览和正式分幕，不要求逐幕点击继续 |
| 生成中改向 | 快捷选项、可选补充文字、指定幕；只改本幕或从这里改后续，边界暂停并确认影响范围 |
| 定稿后修改 | 保留旧确认版本，重写影响范围；其他场景正文保留，重新确认 |
| 历史与恢复 | 新建页可打开最近故事；刷新/离开后恢复会话；导出包含已保留的确认版本 |
| 系列续写 | 确认后创建下一集会话，继承角色快照、历史事实、前集交付及系列方向 |
| 背景 | 大纲同时输出环境规格与提示词；可配置独立图片供应商，失败不阻断剧本 |
| 结束 | 确认后停在 confirmed，允许导出 JSON 和继续修改；没有声音或演绎按钮 |

最近故事 API 首期最多返回 100 条，页面展示最近 8 条。历史确认版本用于核对和导出，本期没有一键把旧版本重新设为当前稿的功能。

## 3. 启动和配置

以下命令在 my-legend 根目录执行，Python 3.12。模型密钥只由后端进程环境注入，不进入前端、示例、日志或 Git。

```powershell
python -m pip install -e 'source/StoryGenerate-0dec8480e3c1b01af66407ff063f825a3fd5dedb[dev]'
python -m pip install -e 'source/my-legend-production[production]'
```

业务 API 和新 Worker 都需要原有 `MY_LEGEND_PRODUCTION_DSN`、`MY_LEGEND_PRODUCTION_RUNTIME`、可选 `MY_LEGEND_PRODUCTION_SCHEMA`。新 API 还需 `MY_LEGEND_STORY_URL` 和 `MY_LEGEND_STORY_TOKEN` 访问现有角色目录服务。现有角色服务按项目原方式启动；新功能不替换角色或账号系统。

```powershell
$env:MY_LEGEND_INTERACTIVE_STORIES='1'
$env:DRAMA_LLM_BASE_URL='http://yunshu.xzmoma.cn:3001/v1'
$env:STORY_LLM_FAST_MODEL='deepseek-v4.1-flash-1017'
$env:STORY_LLM_BALANCED_MODEL='deepseek-v4.1-flash-1017'
$env:STORY_LLM_STRONG_MODEL='qwen/deepseek-v4-pro'
$env:STORY_INTERACTIVE_THINKING='disabled'
$env:STORY_INTERACTIVE_STREAMING='1'
# DRAMA_LLM_API_KEY 通过本机安全环境或部署密钥服务注入
python ops/my-legend/run_interactive_story_worker.py --migrate
python ops/my-legend/run_interactive_story_worker.py
```

迁移创建 `interactive_story_sessions`，不会因 GET 请求自动迁移，也不需要新增媒体来源表。API 按项目既有方式启动/重启：本地业务适配器入口为 `python -m my_legend_production.story_api`，端口 8895；原配置需保留。独立 production CLI 使用服务令牌和固定开发身份，不等同于前端用户登录 API。

前端 `.env.local`：

```dotenv
VITE_USE_MOCK=false
VITE_LOCAL_BACKEND=true
VITE_API_BASE_URL=http://127.0.0.1:8895/api/v1
```

在 `source/fingertip-legend-app` 中执行 `npm ci`、`npm run dev:h5`。登录后从创作页“一起创作”进入，或打开 `/#/pages/story-session/index`。未配置开关时不开放新入口。模型供应商不支持流式时关闭 STORY_INTERACTIVE_STREAMING，改为完整场景分块显示；不假装逐字输出。

图片使用独立的 STORY_IMAGE_BASE_URL、STORY_IMAGE_API_KEY、STORY_IMAGE_MODEL。三项缺一即 disabled，仅交付规格和提示词；提供的两个聊天模型不代表可以生图。图片服务适配器要求 OpenAI 风格 images/generations、b64_json，记录原图尺寸并裁切至 1536×864。两个图片线程并行，独立于正文。图片不送入舞台素材库。

## 4. 前后端契约

所有路径以 `/api/v1` 开始，浏览器只调用业务 API。成功响应 `{code:0,message:"ok",data:...}`，失败使用 HTTP 401/404/409/422 和 detail。生产适配器只接受 output=script，省略时也默认 script；发送 audio/h5 返回 409 STORY_ONLY_OUTPUT_REQUIRED。

| 方法及路径 | 约定 |
|---|---|
| GET /story-options | enabled、story_only、outputs=[script]、默认值、题材与能力 |
| POST /story-sessions | Creation，202 返回快照；HTTP 内不执行模型 |
| GET /story-sessions | 当前业务用户会话摘要及可续写标记 |
| GET /story-sessions/{id} | 完整当前状态、正式场景、待处理修改、指纹、available_actions |
| POST /story-sessions/{id}/commands | 202 返回 receipt 和快照；accepted 不代表修改已生效 |
| GET /story-sessions/{id}/events?after=N | 有授权头的 fetch SSE；Last-Event-ID 可续传 |
| GET 同上，poll=true | 同一事件序列的增量轮询，每批最多 200 条 |
| GET /story-sessions/{id}/backgrounds/{scene_key}/image | 仅当前有效图片，鉴权下载 |
| GET /story-sessions/{id}/export | 当前交付、确认状态、内容指纹、背景与历史确认版本 |

示例创建：

```json
{"idempotency_key":"create-client-unique-001","form":"series","method":"assist","character_ids":["目录中实际角色ID"],"genre":"生活治愈","ending":"happy","series_ending":"open","series_episodes":6,"output":"script"}
```

命令共同字段：command_id、expected_revision。命令对象的 JSON Schema 以 `docs/contracts/interactive/Command.schema.json` 为准。

| kind | 业务参数与约束 |
|---|---|
| select_direction | target_id=返回的方向 ID |
| set_preferences | ending、series_ending、focus_role_id、series_episodes，至少一项；仅首集未开写的大纲确认态；集数 2..24，角色必须已选择，改后重做大纲 |
| revise_outline / change | option_id 或可选 text；可指定 target_id=scene_key，scope=scene/following |
| confirm_change | fingerprint=pending_change_fingerprint，确认实际起点和范围 |
| confirm_outline | target_id=plan_id，fingerprint=outline_fingerprint |
| confirm_script | target_id=delivery.story_version_id，fingerprint=script_fingerprint |
| next_episode | 返回 next_creation，前端用其中的固定幂等键创建子会话 |
| cancel / retry | 仅按 available_actions 提交；未知供应商结果不提供自动重试 |
| retry_background | target_id=失败背景的 scene_key，不影响剧本确认 |

相同命令 ID、相同完整输入返回原 receipt，变更输入返回冲突。版本冲突后刷新快照：前端对 change/revise_outline/cancel 仅在 REVISION_CONFLICT 且新状态仍允许时重试一次；确认类命令不自动重试、不自动确认新内容。网络失败保留原命令及原 ID，重发用于查明是否已接收。

事件信封包含 event_id、seq、session_id、revision、generation_epoch、type、occurred_at、payload。核心事件为 stage.changed、outline.delta/ready、scene.started/text.delta/ready/invalidated、change.accepted/proposed/applied/rejected、background.spec.ready/started/ready/failed/stale、script.ready/confirmed、generation.failed/cancelled。没有媒体自动启动事件。

预览用 attempt_id、chunk_index 定位；新尝试替换旧预览，正式 ready 替换预览，旧 epoch 不发布为当前结果。前端按 seq 去重。连接约 50 秒后重连，离开页面不取消任务。当前版本保留全部事件；游标超前返回 409 并重新取快照，尚未启用事件淘汰。未来启用淘汰时必须另行约定快照恢复码。进度只显示阶段与已完成幕数。

单幕修改保留前后正文；从某幕改后续保留前缀。重规划不得删掉受影响幕，受保护后文同时进入写作上下文。连续性由事实约束、结构检查和用户复核共同保障，本期不恢复反复全文评审/重写，也不宣称已有全面语义验证。

## 5. 留给下游同事的边界协议

故事确认终态是 confirmed。`script.confirmed` 只表示用户选定具体内容版本，不表示调用声音、演绎或动画。新 Worker 不消费旧 audio/h5 会话，新故事 API 不能修改这些旧会话。下游无需在本次合并时修改自身代码。

未来需要接入时，由对方增加明确的“开始制作”业务动作，并在服务端读取会话与 export；不能直接消费 outline.delta、scene.text.delta 或未确认导出。

交接条件必须同时满足：

1. 业务用户有会话访问权限；请求的 session_id、story_version_id 与当前确认版本一致。
2. 会话 stage=confirmed，没有 pending_change；export.confirmed=true。
3. 规范化 JSON 的 SHA256 与 export.content_fingerprint 相同。算法：UTF-8、键排序、紧凑逗号/冒号、不转义非 ASCII、拒绝 NaN；与引擎 fingerprint() 一致。
4. 下游将不可变 StoryDelivery 保存为自己的来源制品，保留 story_id、series_id、episode_id、scene_id、line_id、role_id、版本和父版本。
5. 来源登记、所有者校验、创建制作任务和幂等键由下游业务事务负责。建议键 `story-session:{session_id}:{story_version_id}:{output}`；重复动作不重复付费。
6. 后续用户修改形成新故事版本；已有制作引用原确认快照。不得轮询当前会话并覆盖正在制作的来源。

export 同时提供 session_id、revision、story_version_id、confirmed、content_fingerprint、delivery、backgrounds、version_history。背景用 scene_key 关联故事场景，不充当舞台素材 scene_id。只读取 status=ready 且规格/epoch 当前有效的图片；背景失败和未启用必须允许继续制作。下载接口需要业务授权，不把有时效的浏览器 blob URL 保存为永久制品地址。

演绎侧继续负责音色、表演加工、素材、动作、镜头、时间轴与输出。故事侧不新增像素坐标、骨骼、动画帧或声音供应商配置。本次没有实现新的下游自动接入端点，也没有为其预置来源登记表。

正式多用户接入须把 owner(request) 映射为认证服务端的稳定用户 ID，不能采信请求体 owner_id。仓库现有本地 story_api 是固定 USER 的开发适配器；本次未将整个账号系统升级为多用户系统。会话存储与测试支持不同 owner 隔离，但固定开发身份适配器不能据此作为多租户发布依据。

## 6. 验收、证据与当前限制

浏览器测试使用真实 Vue 页面、HTTP/SSE、会话数据库和 Worker，模型为明确标记的离线夹具。它检验交互与契约，不冒充真实供应商或文学质量验收。真实模型调用另有记录。

```powershell
# 前端目录
npm run type-check
npm test
npm run build:h5
npx playwright install chromium
# 如 Python 不在 PATH，设置 STORY_TEST_PYTHON 为虚拟环境 python 的绝对路径
npm run test:e2e:story
```

测试服务器仅在 127.0.0.1:5194 运行，前端测试端口为 5193；不要把 scripts/story_e2e_server.py 用作正式 API。证据输出在忽略的 evidence/，失败保留 trace、截图与页面快照。可用 STORY_TEST_BROWSER 指定本机测试 Chromium 的绝对路径。

故事专项 Python 测试位于引擎 tests/unit/test_interactive_sessions.py、test_interactive_io.py；生产接入测试位于 production 包 tests/test_interactive_bridge.py、test_interactive_postgres.py。PG 测试必须提供隔离测试数据库，不能指向生产数据。具体本轮数量、模型失败/恢复、跳过项及未验事项以《故事生成独立交付测试记录_20261112.md》为准。

当前已验证 H5 桌面和 390×844 手机视口，未宣称 App 真机、小程序、真实图片供应商、真实 TTS 或动画发布通过。图片接口和 16:9、缓存、取消隔离由离线图片夹具测试。正式上线前仍需产品人员对真实角色样本评估一致性、连贯性及改向落实率；没有同版本对照实验，不承诺固定秒数或提速比例。
